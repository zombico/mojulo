Mojulo tool surface

Every listed MCP tool, placed by what it makes (its ring) and what it does to a thing (its verb). The second view groups the same tools into the packs an agent opens and traces the Workflows rails that chain them. The third is the cosmos cube board: which kinds of game the builder can make today, and which facet holds the rest back.

Tool-call clusters

A pack is the unit the agent opens: one dispatcher tool whose members run as pack_x({ tool, args }). Solid chips are the pack's own members, coloured by verb. Dashed chips are shared tools homed in another pack that this pack also dispatches. The strip under each title is the pack's verb mix.

Orchestration rails

The Workflows ring exists so the agent hands over a list once. Each rail below is a chain of calls the server knows how to run end to end; branches show the alternate paths into or out of the same line.

Retired office packs

Left the surface in 3.1.0. Still registered and callable by name from the CLI and plan steps (with a deprecation warning), never listed or routed to the agent.

A cosmos cube describes a game as six facets. The sweep dry-runs the fixtures, then rolls random cubes against the capability registry, and counts which would be makeable. It builds nothing. It runs as a script (node scripts/cosmos-sweep.mjs), not as an MCP tool, so it does not appear in the matrix.
