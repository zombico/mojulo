# Layered raccoon: named surface attachments

This is the next reviewable experiment after the spatial wire reference. It proves
that one change to primary form can reposition details through named surface
frames. It uses the native pure helper `control/lib/graph/polygonizer/surface-pin.js`
and the existing wire renderer. It is not a registered tool, a full station-loft
builder, a topology editor, or a rig.

## Artifacts

Kept here: `recipe.json` (explicit named surfaces, parts, attachment pins and local
offsets), the compiler, the tests and `validation.json`. Everything rendered lands in
the gitignored `lite-template/integration/0924/spike-output/``raccoon-layered/` (override with `MOJULO_SPIKE_OUT`):

- `comparison.svg` / `comparison.png`: primary-only, baseline, and deformed heads in quarter/profile.
- `baseline-*.svg`: original detailed head re-expressed as attached parts.
- `deformed-*.svg`: skull width 1.18, muzzle length 1.30; same attachment recipe.
- `primary-*.svg`: L1 only, with detail and crease channels off.
- `baseline.json`, `deformed.json`, `primary.json`: compiled spatial sources.

Every SVG embeds its source and camera metadata; paths retain named point IDs as
well as spatial edge intervals. The comparison is vector SVG, not embedded images.

## Layer boundaries in this experiment

| Layer | Implementation |
| --- | --- |
| L0 | Explicit z-up/+y-front frame; fixed authored scale |
| L1 | Two closed primary parts: skull and muzzle, with named points/faces |
| L2 | Closed ears/eyes attached to skull; closed nose attached to muzzle |
| L3 | Brow creases reference existing skull edges, adding no vertices; open ear insets attach to ear surfaces and declare exact boundary edges |
| L4 | Existing named region assignments, separate from point placement |
| L5 | Shared wire renderer: contour/feature/plane style and camera |

The fixture imports the previous head's authored topology. It deliberately does
not invent station identities for a mesh that was not originally generated by a
named station grammar. Vertices carry layer, part and named anchor provenance;
station/slot generation remains a future authoring boundary. IDs here are explicit
recipe keys and survive map reordering. Insertion/deletion cannot silently change
their meaning; deleting a referenced face fails, rather than using nearest geometry.

## Surface frame contract

A pin declares a parent part, face ID, three barycentric weights, a directed edge
on that face and handedness. The frame's origin lies on that face; its normal comes
from oriented winding, tangent from the named edge, and bitangent from the explicit
handedness. Local offsets are stored in this frame, never recomputed from screen
coordinates. Positive normal offsets place detail above the surface; the origin
being attached does not mean every detail vertex lies on the surface.

Pins are authored against the imported fixture once. The compiler does no nearest
face search. Ears use symmetric front-skull facets, not arbitrarily different
triangles on the rounded back. Left/right attachments name corresponding directed
edges with explicit handedness, so width changes preserve symmetry. Degenerate
frames are errors. No tangent-frame transport through topology changes is claimed.

The skull's x coordinates respond to width. The muzzle's depth responds to length
about its fixed rear plane. Details keep their local dimensions; their positions
and orientations follow the newly evaluated parent frames. The nose therefore
follows the stretched muzzle, while the brow stays on the widened skull's existing
edges. The primary parts remain separate overlapping closed shells, not a boolean
union. The assembled silhouette can change when ears are enabled.

## Checks and limits

Per-part audit: expected boundary edge set, non-manifold edge count, oriented edge
consistency and triangle degeneracy. Closed parts require no boundaries; open ear
insets require exactly their three declared edges. This is not a self-intersection,
inter-part clearance, printability or deformation certification. The imported
parts overlap by design.

Tests compare baseline vertices against the previous head, verify closure before
and after the edit, recover every detail's unchanged local offset, check mirrored
pairs, reorder input maps, delete a named anchor, and disable detail/crease channels.
Turning details off emits no L2/L3 detail geometry. Turning creases off changes no
vertices or faces. The previous renderer's default SVG bytes remain unchanged.

Human review should inspect both quarter and profile comparisons, then front/back:
recognition and line quality, detail placement, seams, and depth. The exaggerated
variant is a diagnostic edit, not a claim of improved raccoon proportions. The
native adapter is internal and not exposed through a tool or recipe-book toolkit.

## Reproduce

From the repository root (Node as required by `control/package.json`, Python with
the existing wire example's NumPy/Pillow dependencies):

```sh
node --test docs/examples/raccoon-layered/test-layered.mjs
python3 docs/examples/raccoon-layered/render.py
cd control
npx vitest run lib/graph/polygonizer/surface-pin.test.js
```

`recipe.json` was authored once by `seed-recipe.py` from the imported wire head; re-running
it reproduces the file byte for byte. It is the authoring record, not part of the render path.

No Blender, image generation, server or database is required. The renderer invokes
the JavaScript compiler so artifact production exercises the native pin helper.
Do not commit until the user has reviewed this artifact set.
