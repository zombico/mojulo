## 1. What mojulo is

A **single-user, self-hosted control plane** whose real interface is a **localhost HTTP MCP server** (~144 tools). The dashboard, chat builder, and wizard are different faces over the same primitives; the operator drives everything from a host MCP agent (Claude Code / Codex). The substrate's self-description is "PLAYful Cloud" — **P**ersistent, **L**ocal, **A**gent-**Y**oked: bindings keep running after the chat ends, everything lives on the operator's host, and the agent is the inference/vision layer so mojulo holds no LLM credentials on those paths.

Three creatable artifact paradigms:

| Paradigm | What it is | Entry tool |
|---|---|---|
| **Bot** | Deployed chatbot process (Docker/Fly), own SQLite, hash-chained turns | `infer_intent` → `save_modular_bot` |
| **Connected Service** | Skill synthesized into the host adapter, or a materialized mcp-orbit composition over the operator's installed MCPs | `get_catalyst` / `meta_context_declare_inventory` → `bind_primitives` |
| **App** | Local long-running process + MCP sidecar; inference parked back on the agent via the agent-tasks queue | `install_scaffold` → `meta_context_commit({type:'app_materialization'})` → `start_app` |

Two-package monorepo: `control/` (Next.js 16, port 3001 — bot factory, dashboard, MCP server) and `lite-template/` (Express 5, port 3000 — the bot runtime staged into per-bot artifacts and published as the GHCR image).

## 2. The orientation layer (Ring 0) — how a new agent self-orients

[control/lib/mcp/tools/context.js](../control/lib/mcp/tools/context.js) is the whole progressive-disclosure design in one file:

- The MCP `initialize` preamble is deliberately short (~180 words). Everything heavier lives behind **`forward_context`**, which is an **index, not a glossary**: a lean opener, a *routing index* (user-framing → entry-tool rows), a drawer directory, the commitment-level floor, and two standing safety one-liners.
- **Drawers** (pull on demand): `get_register_kit` (concept glossary), `get_tool_index` (full ring-grouped one-liner index), `get_deliberation_overview` (Ring 6 structural model), `get_ui_map` (dashboard pages), `get_substrate` (PLAYful Cloud positioning).
- **Register tuning**, two axes resolved per call as *override > operator anchor > defaults*: `vocabulary_register` (plain / mixed / mojulo — user-facing phrasing only; concept names and tool descriptions are invariant) and `procedural_disclosure` (terse / reflective / pedagogical narration).
- **Commitment-level floor** — four gate distinctions that must stay legible at every register: *proposed vs materialized*, *dry-run vs promoted*, *watched vs read-once*, *sealed in the audit trail vs not recorded*.
- The `custom_protocol` author's guide also lives here; its Step-0 posture check disambiguates **protocol** (fires inside a bot turn) vs **catalyst** (after-the-conversation workflow) vs **skill** (personal automation) — the most common misfire.
- A registry-sweep test in `context.test.js` enforces that every listed tool appears in `TOOL_INDEX`; adding/removing a main-flow tool means updating `TOOL_INDEX` + `ROUTING_INDEX`. A new `create_view` kind or `compose_world` base needs a **view-vocab card**, not an index row.

## 3. The ring model (registration order in [server.js](../control/lib/mcp/server.js))

Pure JSON-RPC 2.0 dispatch (`dispatchMcpRequest`); the Next.js route owns HTTP + bearer auth; `userId` is always `'local'`. Loopback-only, no auth layer — never expose or tunnel it. `listed:false` keeps retired tool names executing as unlisted aliases. All invocation flows through `instrumentedInvoke` (telemetry, new this branch).

- **Rings 0–1, build & operate.** Intent → protocol recommendation → identity/form/appointment/triage/optical-read config generation → `save_modular_bot` compiles a zip. The composer ([control/lib/composer/](../control/lib/composer/)) stacks protocol cartridges (`00_base` … `05_optical-read`) into `instructions.txt`; [deployers/docker.js](../control/lib/deployers/docker.js) stages lite-template, writes config, bakes `config/embeddings.json`, zips. Five protocols ship: `knowledge`, `formGathering`, `appointments`, `triage`, `opticalRead`. Operate reads proxy through [bot-proxy.js](../control/lib/deployers/bot-proxy.js) — **conversation data never enters the control-plane DB**. Fleet tools aggregate; `verify_fleet_chains` walks the per-turn `content_hash`/`chain_hash` tamper-evident chain across bots, extending across federated triage handoffs (`handoff_hash` = sender's tip-of-chain).
- **Ring 6, deliberation.** The contextmap (`meta_context_brief` / `meta_context_commit` — append-only *why*, six typed commit events), inventory declaration (replace-semantic snapshot of the operator's installed MCPs), vendor capability research (`record_mcp_capabilities`, transactional supersession with history), the mcp-orbit composer (five component kinds: mcp × trigger × pattern × idempotency × render; five per-provider states routing remediation), `bind_primitives` (fills a role template with the operator's *actual* installed tool schemas), `bind_trigger` (cron activation, fires only when the scheduler daemon is enabled), `declare_skills` (host-skill mirror), and `semantic_search` (fuzzy recall over all durable state — principles, capabilities, catalysts, sketch/view vocab, painted-landscape glyphs).
- **Ring 7, apps & runtime.** `install_scaffold` → materialization commit → `start_app` (app + MCP sidecar spawned atomically). The app POSTs inference to `/api/app-inference/envelope`; the agent fulfills via `pull_agent_task` → `submit_envelope_inference` (canonical loop: the `run-inference-worker` catalyst, or `MOJULO_AGENT_RUNTIME=claude-code-headless`). Daemon host gating: `MOJULO_DAEMONS=enabled`, per-daemon `MOJULO_TRIGGER_RUNTIME` / `MOJULO_APP_RUNTIME`. Agent-routed builder chat: `emit_chat_signal` / `request_chat_decision`.
- **Ring 8, plan mode.** Plans are the PROPOSED layer (contextmap is sealed reality). Lifecycle: `forge_plan` → `revise_plan` → `compile_plan` (validates the manifest against the *live* tool registry) → `execute_plan` (per-execution `confirm:true` gate, stops on first failure). `sketch_plan` previews the manifest as a pipeline diagram.
- **Ring 9, stash · gather · cook (+ legacy research).** Typed intake (`mint_stash` → `gather`, 8 item types validated at the gate) → `cook` nucleates ONE outcome per singular aim into a self-contained folder at `/outcomes/<cook_ref>/` (14 publication kinds, essay → comic → `site`; the **agent** authors `report_md` — no server-side LLM). `forge_publications` cooks 2–4 candidate kinds at once; `recommend_kind` is rules-based. Legacy diffuse-research tools coexist behind `enter_research_mode`.
- **Ring 10, visualization** — the largest surface; see §4.
- **Ring 11, operations mode.** Ops tags: a domain title + descriptor (the thesis) + members drawn from committed reality. **Consulted, not driving** — no execute/deploy/mutate from this mode.

## 4. Visualization substrate ([control/lib/graph/](../control/lib/graph/))

**Recipe→render architecture**: stored manifests are tiny recipes; per-kind assemblers regenerate geometry deterministically on render. [worlds/world-scene.js](../control/lib/graph/worlds/world-scene.js) is the single `kind → assemble*Scene` dispatch seam feeding both the live World route and `.glb` export; per-kind descriptors (assembler, title, `walk`/`fogBoxes` capability flags) live in the [worlds/world-kinds.js](../control/lib/graph/worlds/world-kinds.js) registry, one row per kind.

Four renderer backends over one engine-agnostic payload (`{faces, cameras, viewBox, unitScale, …}`):

1. **SVG** — two-point-perspective flatten (`projectTwoPoint`); the "Scene / looked-at" tier. `sketch/` handles manifest derive/diff/validate/PNG.
2. **CSS-3D** — [scene/scene-css3d.js](../control/lib/graph/scene/scene-css3d.js): every planar face → a `matrix3d`-positioned div; dependency-free HTML; live turntables via `create_solid_turntable`. Baked lighting model in [scene-css3d-lighting.md](scene-css3d-lighting.md).
3. **three.js / WebGL** — [scene/scene-three.js](../control/lib/graph/scene/scene-three.js): traversable Worlds with orbit/WASD, vendored three, exportable via `export_model` (.glb). The "World / moved-through" tier. The emitter is registry-driven: per-channel page scripts live in [scene/channels.js](../control/lib/graph/scene/channels.js) (`RUNTIME_CHANNELS` — one row per channel: filter, script, emitted header, `__mojStep` slot), the headless-capture bridge names in [scene/capture-contract.js](../control/lib/graph/scene/capture-contract.js), string-safety + delivery-mode helpers in [scene/emit-util.js](../control/lib/graph/scene/emit-util.js). Emission is pinned byte-level by a 36-fixture characterization net (`emit-channels.char.test.js`) + a V8 parse gate (`emit-parse.test.js`); AO bakes are LRU-memoized in-process (geometry-keyed, colors excluded — ~24× on repeat renders).
4. **GLSL raymarch** — painted-landscape raymarch + the volumetric effects overlay (fog) that composites OVER three.js worlds, occluding via a grid-culled scene SDF. Principles in [raymarch-effects-layer.md](raymarch-effects-layer.md).

Shared lighting primitive: `polygonizer/vexar.js` (directional Lambert, one dot product per face). Subsystem weight: `polygonizer/` (~321 files — the geometry core), `views/` (~81 — math/science/bio + view-vocab cards), `worlds/` (~32 — physics sim, event bus, game idioms, controllable worlds, the new `operator-world.js`), plus `scene/`, `effects/`, `landscape/`, `machina/`, `figures/`, `vehicles/`, `city/`.

Entry tools by intent: `create_sketch` (diagrams/charts; vocab via `semantic_search({kinds:['sketch_vocab']})` + `get_sketch_vocab`) · `create_view` (45 science/math/bio study kinds; manuals via `get_view_vocab`) · `compose_world` (base × theme: city, transport-hub, controllable, action games, operator-state, planetary, painted-landscape, math) · `create_figure` (posed protoform bodies, gait GIFs) · `create_beats` (synthesized audio artifacts — ambient loop / composition / pattern groove / SFX; cards via `get_beats_vocab` + `semantic_search({kinds:['beats_vocab']})`) · `create_game` (playable level artifacts over the game store/contract spine; completability-gated at mint — see §6; vocab via `get_game_vocab` + `semantic_search({kinds:['game_vocab']})`) · `create_workbench` / `create_assembler` (lathe polygomers → assemblies) · `create_carved_solid` (extruded metal wordmarks) · `create_manji_tree` (cardinal-grammar IR) · `forge_motion` / `stitch_motion` (camera clips, chart decks, MP4 films) · `reference_protocol` / `capture_reference` (the agent as vision adapter for photo references — no image ever sent to mojulo) · `measure_view` (real-unit time-series read-back) · `verify_machina` (checked feasibility verdicts).

## 5. Bot runtime ([lite-template/](../lite-template/))

Express 5 + better-sqlite3. Fully **local RAG**: `helper/vector-rag.js` boots from the baked `config/embeddings.json` and embeds queries in-process via `helper/embedder-local.js` (`Xenova/multilingual-e5-small` ONNX q8) — same vector space as the control-plane build; fails loudly, no keyword fallback. Turns are hash-chained (`content_hash` + `chain_hash`, SHA-256); `/handoff` writes `event_type='handoff'` rows carrying the sender's tip-of-chain for federated triage. Prometheus `/metrics`. Embeddable widget via `<script src="${botUrl}/widget">`. Landmines: onnxruntime-node is glibc-only (Debian slim, never Alpine); model weights are gitignored and fetched at install.

## 7. Invariants a new model must not violate

- Conversation data never moves into the control-plane DB; per-bot reads go through the bot proxy.
- All builder paradigms converge on `buildDeploymentConfig()` — no paradigm-specific branches downstream.
- Bot turns go through the hashing helpers; never bypass `content_hash` / `chain_hash`.
- The bot image is bot-agnostic; Fly injects per-bot config as files. Pin exact bot tags, never `:latest`.
- `forward_context` stays a thin routing index; heavy orientation lives behind drawers.
- MCP transport binds to localhost only; no tunnels, no auth layer assumed.
- The dashboard is not a conversational surface (the bot builder chat is the deliberate exception).
- Never `cat`/`Read` a `.env` under `$MOJULO_HOME` or in an unzipped bot — use `inspect_bot_env`.
- No intent-classification / use-case gating layers; capability and suitability assessments belong to the operator ([responsibility-model.md](responsibility-model.md)).
- Synthesize ≠ certify: dry-run on one real input → inspect → promote. Re-validate on schema drift.

## 8. Design signature (the taste that should carry into new work)

- **Progressive disclosure everywhere**: thin index → drawers → vocab cards; context cost is paid on demand, never front-loaded.
- **Recipes, not renders, in the DB**: tiny deterministic manifests regenerated on render (a painted landscape is ~30 tokens vs ~14K of raw SVG).
- **Append-only deliberation separated from replaceable present-state**: contextmap (why, sealed) vs inventory (what's installed, replace-semantic) vs outcomes (what fired, never written to contextmap).
- **The agent is the inference and vision layer**: apps park inference on the queue; photo references are read by the agent's own eyes; cooks are agent-authored. Mojulo needs no keys on those paths.
- **Closed vocabularies + seeded determinism** for generative surfaces: glyph cards, heartbeats/splatches, view-vocab — content-extensible by dropping a card, code-extensible only for new families.

## 9. How mojulo accreted (origin & stance)

None of the architecture above came from a roadmap. It accreted, each layer built exactly deep enough to unblock the next — and that history explains the shape better than any spec would.

**The chain.** Mojulo began as an enterprise/sovereignty play, disrupted by frontier-lab capability announcements; the author built in stealth and pivoted continuously before open-sourcing the initial chatbot layer. An MCP experiment then unlocked the connected-services platform → **metacontext** became necessary so composed tools wouldn't sprawl or repeat → which extended naturally to vibe coding, then spec writing → mojulo was already Node.js, so a **runtime** followed → then the idea of the agent writing to the app and harnessing the filesystem + event bus → the system got complicated enough to need a **chart-rendering tool to depict itself**. Then, for reasons unknown, the author applied two-point perspective, draughtsmanship, and mandala principles to fake perspective with divs and CSS → **pure-world**: all vector, no pixels, map everything there first → frame-by-frame animation (each shot is a moment in time; frames stitch to GIFs, GIFs stitch to movies) → the **figure** → three.js made worlds walkable → live objects moving in code brought in **physics** via experiments → which accreted into the science explainers, culminating in the black-hole viewer → and Newtonian physics was clawed back into the world renderer and its own event bus.

**Stances a new model should hold:**

- **No onboarding is the product.** The coined lexicon isn't a tax to be mitigated — the ask-and-discover loop is the intended interface. You ask what it can do, it gives you clues, and agent + operator build something interesting together. The bug class to watch for is *dead-end clues* (terms that don't reward the question), not unfamiliar terms per se.
- **The frontier moves; layers get second passes on demand.** Surfaces held at Phase-1 depth are not debt — each was built to unblock its successor. A layer deepens when something downstream demands it (physics → world renderer is the exemplar). Per task, ask: is this layer still at the frontier, or has something started demanding its second pass?
- **Pure-world (all-vector, no-pixels) is the load-bearing constraint** of the entire visual arm. It's what keeps recipes tiny, makes animation stitching rather than rendering, makes diffs structural, and makes real-unit read-back (`measure_view`, SI-honest experiments) possible. New visual work should keep the world pure-vector.
- **Happy to fail.** The visualization shift adds positioning complexity *and* a unique shot at one-shotting something nobody has done. Weight advice toward "does this make the one-shot better and the failure legible/cheap," not conventional prudence. The two arms (control plane, visual substrate) should feed each other — the `operator` world base (mojulo rendering its own state as a walkable world) is the synthesis pattern.
- **The self-depiction loop is a compass.** Twice now, tools built to depict the system's own complexity have become product (chart rendering → Ring 10). When guessing what accretes next, trust that engine.
