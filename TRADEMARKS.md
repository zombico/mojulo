and 42). The code is open source under the [Apache License 2.0](LICENSE) and you are welcome to fork it,
change it and ship it. The licence grants no rights in the name (section 6 says so). This page says how the
name may be used, so that "mojulo" keeps meaning the project it names.

The short version: **fork freely, under your own name.** "Powered by mojulo" describes your project; it is
never part of its name.

## Fine without asking

- **Redistributing mojulo unmodified** under its own name: mirrors, container images, distribution packages.
  Changes made only to package or install it on a platform count as unmodified.
- **Saying truthfully what your project is**, in a description, README, tagline, docs or talk: "a fork of
  mojulo", "powered by mojulo", "built on mojulo", "works with mojulo", "export your mojulo recipes to Foo".
- **Writing, teaching and talking about mojulo**: articles, tutorials, videos, courses, reviews, comparisons.
- **Linking to mojulo** and naming it in a list of tools you use.

## A fork that changes mojulo needs its own name

If you distribute a version of mojulo that changes how it behaves, give it a name of your own in every place
a user meets it:

- the product name and the UI title;
- the package name (npm, PyPI, any registry) and the command people type;
- the MCP server name a host displays, and plugin, marketplace and registry listings;
- the repository or organization name of a fork you distribute as its own project (a fork kept to send
  changes back upstream may keep the name).

These may stay as they are: internal identifiers, environment variables, file and directory paths, code and
comments, and the copyright notices. [NOTICE](NOTICE) must stay; the Apache licence requires it.

## Never

- **"mojulo" in a name** you give a product, project, company, service or hosted offering, or in a domain
  name, account or social handle.
- **Anything confusingly similar**: misspellings, sound-alikes, abbreviations or "mojulo" with a word added
  ("mojulo-pro", "mojulo cloud", "mojulo for Unity", "Foo mojulo", "mojuloX").
- **Implying the maintainer endorses, certifies, sponsors or operates** your project, product or service.
- **The mojulo logo or visual identity**, except to refer to mojulo itself.

## Descriptors, done right

Your own name comes first and stands out most; mojulo is named in plain text, after it, as a description.

| Fine | Not fine |
| --- | --- |
| Foo — powered by mojulo | mojulo Foo |
| Foo, a fork of mojulo | Foo mojulo |
| Foo (built on mojulo) | mojulo-foo, foo-mojulo (as a package, repo or domain) |
| hosted Foo, powered by mojulo | mojulo hosting, mojulo cloud |

## Asking

Unsure, or want a use this page does not allow (an event, a partnership, a community group)? Write to
`hello@mojulo.ai` with `[mojulo trademark]` in the subject. Permission counts only when it is given in writing.

If we ask you to change a name, it will start as a friendly note. Forks are welcome; we only ask that they
carry their own name.
